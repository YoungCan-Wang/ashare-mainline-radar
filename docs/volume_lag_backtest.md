# volume_lag（量先行/滞涨观察）研究回测

观察层（observation layer，只看不买）研究，**不**写入 Daily 选股，**不**进入 `next_buy`，**不**落 Supabase。红色闸门即使以后采集也仍冻结开仓。

结论先说：**NO-GO，不要采集进 Daily。**

## 复现

```bash
python3 scripts/run_volume_lag_backtest.py --count 520 --max-symbols 360 --output reports/backtest/volume_lag_backtest.json
```

本次云环境实跑：TickFlow free API，未复权日 K，请求 360 只、实际扫描股票 307 只（去掉 ST/ETF 等），日历 2024-10-28 至 2026-09-14，warmup 60 日，455 个有信号截面日。样本外（sample-out，留出检验）为 2026-02-12 至 2026-09-07。费用复用仓库 `TradingCostModel`（佣金/证管费/经手费/过户费/印花税 + 双边 5bp 滑点）。

入场：信号日 T 收盘后选股，T+1 开盘买入（开盘涨停不成交）；持有 1/3/5 个交易日收盘卖出。对照：同日同规模随机、成交额 TopN、accumulation 近似（低位+5/20 日成交额比抬升+5 日止跌）。

## 规则（v1 假设，可配置）

| 条件 | 阈值 | 中文理解 |
| --- | --- | --- |
| 量 | 当日成交额/自身近 20 日均值 ≥ 1.50x **或** 截面成交额分位 ≥ 80% | 相对自己放量，或当天全市场偏热 |
| 价滞 | 当日涨跌 ∈ [-1%, +2%]，5 日涨幅 ≤ 8%，主信号距 20 日高点 ≤ -3% | 放量但价格没走出来 |
| 位置 | 主信号 60 日区间位置 ≤ 70%；低位 ≤ 55%；>70% 记高位滞涨 | 低位 vs 高位出货风险分开看 |
| 排除 | ST / ETF / 涨停收盘 / 一字板 | 不可交易或不可比 |
| 主题加权 | v1 不做 | 主线成立但跑输主题均涨，留给以后 |

每日最多 12 只。高位放量不涨只做诊断，不进主信号。

## 解读

1. **低位并没有正期望。** 样本外 1169 笔，扣费后均值 -57bp，中位数 -89bp，胜率 43.8%。笔数足够，不是噪声样本。
2. **低位还弱于简单成交额 TopN（-15bp）和同规模随机（-47bp）。** “价格滞后”过滤在这段样本上是减分项，不是 alpha（超额收益）。
3. **训练窗已经输给随机（+21bp vs +55bp）和成交额 TopN（+47bp）。** 不是“样本内好看、样本外变脸”那么简单，规则本身就没有稳定边。
4. **高位滞涨样本外均值 +12bp，但中位数 -79bp、胜率 43%。** 右偏、路径回撤约 -5%，正是出货/滞涨风险画像，不能当成采集理由。
5. **滚动三折从 +66bp 衰减到 -34bp。** 近期样本更差，不支持“现在开始 Daily 观察”。

过线条件（预先写死，未按结果改）：样本外低位或全体，次日开盘持有 5 日，扣费后均值 ≥ 10bp，笔数 ≥ 80，且同时高于成交额 TopN 与随机。本次低位、全体都未过线。

## 建议

**不要把 `volume_lag` 采集进 Daily。** 现有 `accumulation`（低位放量转强）和 `strong_stock`（已经在涨且有量）继续各管各的。若以后重做，应先换假设（例如必须站回均线、或只要主题内相对滞涨），而不是把当前阈值写进生产。
