# 运行与场次

日报由 GitHub Actions 工作流 `daily-mainline.yml` 触发。频率闸门与场次身份由 `workflow_frequency.daily_session` / `should_run_workflow` 定义。时区固定为 `Asia/Shanghai`。

## 场次窗口

```
MARKET_OPEN  = 09:30
MARKET_CLOSE = 15:00
```

`post-close`（收盘后场次）：交易日 T 的 15:00 起，至下一交易日 09:30 之前。隔夜、周末与节假日仍归属 T。日历日零点不切换 Daily 身份。

`pre-close`（收盘前场次）：交易日当日 09:30 至 15:00 之前。

无 `last_bar_date` 时的判定：

| 北京时间 | 场次日 | `after_close` |
| --- | --- | --- |
| 工作日 ≥ 15:00 | 当日 | true（`post-close`） |
| 周末 ≥ 15:00 | 上一工作日 | true |
| 周末，或工作日 < 09:30 | 上一工作日 | true |
| 工作日 09:30 ≤ 时刻 < 15:00 | 当日 | false（`pre-close`） |

传入 `last_bar_date`（环境变量 `RADAR_LAST_BAR_DATE` 或 `DATA_AS_OF`）时：日历日等于最后一根 K 线日则按当日开收盘切分；周末或未开盘则停留在最后一根 K 线日的 `post-close`；已过当日 15:00 且最后一根 K 线早于日历日时，仍停留在最后一根 K 线日的 `post-close`。

`session_as_of(now)` 返回场次日。CLI 未指定 `--as-of` 时用该日期截断行情与情报，使延迟到周末的补跑仍对齐 T。

## Daily 幂等

`policy=daily`：同一场次日、同一 `pre-close` / `post-close` 已有成功运行则跳过。盘前手动成功不阻止当日 `post-close`。失败运行不占额度。`force=true` 绕过闸门。

查询范围：同分支、已完成的 workflow runs，最多 30 条。频率检查失败时默认关闭（`should_run=false`）。

## 定时与手动

| 工作流 | 触发 | 频率策略 |
| --- | --- | --- |
| `daily-mainline.yml` | 工作日 cron `45 8 * * 1-5`（北京 16:45）；`workflow_dispatch` | `daily` |
| `quote-refresh.yml` | 工作日北京 10:30 / 11:30 / 14:00 / 15:10 | 无 Daily 场次闸门；行情日期非当天则跳过写入 |
| `strategy-backtest.yml` | 仅手动 | `backtest`：同一 commit 24 小时内成功则跳过 |
| `sync-theme-baskets.yml` | 周日北京 20:00 | 与日报分离；篮子有变更时单独提交配置审查 |

日报默认 `mode=universe`、`max_symbols=0`，先跑测试与仪表盘构建，再 `scripts/run_daily.py`。Artifact 名 `ashare-mainline-radar`，保留 90 天。`main` 分支成功后部署静态作战台。

## 并发

`daily-mainline.yml`、`quote-refresh.yml`、`strategy-backtest.yml` 共用并发组：

```
concurrency:
  group: tickflow-api-${{ github.repository }}
  cancel-in-progress: false
```

同一组同时只跑一个 job，后到的排队，不取消进行中的运行，避免 TickFlow 配额互相打断。
